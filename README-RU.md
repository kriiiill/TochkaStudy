# Учебный портал «Точка Связи» — авторизация

Этот проект переводит текущий HTML-портал в Next.js для Vercel. Файл портала находится в `private/portal.html`, а не в `public/`: браузер получает его только через `/api/portal` после проверки сессии Supabase и активной роли в таблице `portal_users`.

## Важно
- Это подготовленный проект, а не уже опубликованная версия. У меня нет доступа к вашему GitHub/Vercel/Supabase, поэтому я не мог развернуть его от вашего имени.
- Не переносите старый публичный `index.html` в `public/` и не оставляйте старый статический деплой как общедоступную копию — это обойдёт авторизацию.
- `SUPABASE_SERVICE_ROLE_KEY` — секрет. Добавляйте только в Vercel Environment Variables без префикса `NEXT_PUBLIC_`. Никогда не вставляйте его в браузерный код и не отправляйте в чат.

## Настройка
1. Создайте проект Supabase.
2. В SQL Editor выполните `supabase-setup.sql`.
3. В Authentication → Providers → Email оставьте включённым вход по email/паролю. Публичную регистрацию не добавляйте в интерфейс; учётные записи создавайте вручную через Supabase Dashboard → Authentication → Users → Add user.
4. В Vercel добавьте переменные из `.env.example`: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`. Значения берутся в настройках API проекта Supabase. После добавления переменных сделайте Redeploy.
5. Разместите содержимое папки проекта в GitHub-репозитории, подключённом к Vercel. Vercel должен определять приложение как Next.js; Root Directory — корень проекта.
6. После создания пользователя скопируйте его UUID из Authentication → Users и выполните в Supabase SQL Editor запрос, подставив UUID:

```sql
insert into public.portal_users (user_id, role, active)
values ('UUID-ПОЛЬЗОВАТЕЛЯ', 'admin', true);
```

Для сотрудников используйте роль `'employee'`. Чтобы отключить доступ, установите `active = false`:

```sql
update public.portal_users set active = false where user_id = 'UUID-ПОЛЬЗОВАТЕЛЯ';
```

7. В Supabase отключите публичную регистрацию, если она не нужна. Создавайте пользователей только вручную. Для реального использования включите MFA для администраторов и используйте уникальные пароли.

## Текущие ограничения
- Роли `employee` и `admin` проверяются сервером, но отдельная административная панель для управления учётными записями пока не реализована: создание/отключение выполняется через Supabase Dashboard и SQL.
- Для текущего небольшого портала (до 30 человек) это снижает сложность и не требует хранения паролей в собственной базе. Supabase хранит и проверяет пароли.
- После успешной проверки HTML портала отправляется авторизованному браузеру; как и любой отображаемый пользователю контент, его можно сохранить после входа. Задача защиты — не дать неавторизованным пользователям получить исходный файл.
- Перед продакшеном проверьте весь функционал портала после переноса на Next.js. Данный проект не должен публиковаться поверх текущего сайта, пока не настроены Supabase-переменные и первая запись администратора.
